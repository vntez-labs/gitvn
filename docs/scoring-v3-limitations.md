# Scoring V3 limitations

- Public activity has an observation bias. Private, internal and restricted repository records never earn points. The existing GitHub calendar can show separately authorized aggregate activity, which is outside the scoring evidence.
- GitHub reports commit contributions per repository and day. The adapter reads up to 50 repositories and 100 daily groups per repository. Complete daily groups support cadence independently of commit identity. A follow-up inspects up to 100 default-branch history entries for each of up to 25 public repositories in one request, plus one page each for up to five unresolved repositories in a second batch. A repository/date is reconciled when its count matches the distinct commit OIDs observed on that date. Matched dates can support project qualification and confirm empty single-parent commits by tree ID. Default-branch history can miss other branches, rewritten history, attribution differences and entries beyond the cap. The adapter retains partial volume or coverage where the evidence still leaves those metrics unresolved.
- The adapter reads up to 100 records each for PRs and issues and up to 200 review records. It inspects up to eight reviews per authored PR and the most recent close event per authored issue. Missing pages and fields are explicitly marked. Contributions that began before the window, deleted actors, and outcome records GitHub cannot expose can undercount collaboration. A closure with no visible closer stays partial.
- GitHub release counts, stars, forks and followers are current lifetime snapshots. The owned original repository query is bounded to 100 results and checks up to five releases per repository for a published release. A truncated sample containing only drafts leaves release evidence incomplete. Personal ownership favors individual repositories over those owned by organizations. GitHub's fork count does not identify fork owners, so external fork activity is approximated by GitHub's count on original public repos.
- Archived state is retained as metadata. Valid evidence gathered while a repository was active remains eligible inside the window. The pipeline has no historical repository state snapshots.
- The synthetic calibration suite tests formula behavior and visibility loss. Population calibration requires authorized GitHub GraphQL access and a sampling protocol. Results here cannot establish how many real profiles reach each rank.
- The app was verified locally. A deployment preview with authenticated GitHub access remains the place to verify live query cost, partial response behavior, and production UI rendering.
